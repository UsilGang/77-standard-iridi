## Краткое резюме

Встреча посвящена ускорению работы над **«Стандартом автоматизации iRidi»** — единой энциклопедией технических решений для инсталляторов, продаж и ИИ-агентов. Уже готовы черновики **архитектуры Bus77** (с Машей) и **освещения**; узкое место — **технические схемы и типовые решения**, которые плохо генерируются «в лоб» из текста.

Консенсус: книга — не PDF для печати, а **живая база знаний** для:
1. обучения продажников и новых инсталляторов;
2. контекста ИИ (продажный + технический агенты);
3. автоматического обновления после **экспертных советов**.

Отдельно сформулирована **межотдельная модель обмена**: отделы сливают в общий **коллектор сырые данные** (записи встреч, полевой опыт, релизы продуктов), каждый обрабатывает их **своим органайзером**; стандарт и Wiki — общий «жёсткий слой» проверенных знаний.

## Цель стандарта автоматизации iRidi

**Единый, повторяемый язык** проектирования, монтажа и сдачи объектов умного дома на базе Bus77 / iRidi:

- снизить хаос «каждый проект по-своему»;
- дать новичку готовую «обвязку» без изобретения велосипеда;
- опытным интеграторам — общие правила и типовые узлы;
- бизнесу — масштабирование без зависимости от «звёзд»;
- ИИ — канонический контекст для ответов, проверки продаж и дополнения разделов.

Аудитория книги (из самого стандарта, разд. 1): начинающие инсталляторы, опытные интеграторы, владельцы бизнеса и РП.

## Идея обмена информацией между отделами

```
Поле / экспертный совет / релиз продукта
        │
        ▼
   Коллектор (сырые данные, общий для компании)
        │
   ┌────┴────┬────────────┬──────────────┐
   ▼         ▼            ▼              ▼
Органайз    Органайз     Органайз       …
продаж      продукт      пресейл/ЦИК
   │         │            │
   └────┬────┴────────────┘
        ▼
  Предложения изменений в Стандарт + Wiki
        │
        ▼
  Эксперт / автор раздела (approve) → публикация
```

**Ключевые принципы с встречи:**

| Принцип | Смысл |
|---------|--------|
| **Сырые данные в коллектор** | Не обмениваться уже обработанным текстом между отделами — каждый department-specific органайзер |
| **Экспертный совет → материал** | Каждая сессия интеграторов = вход для обновления стандарта |
| **Два слоя ИИ** | Агент продаж (ценности, демонстрация) + агент техники (корректность решений) |
| **Обратная связь продавцам** | Анализ звонков/чатов → «здесь не так объяснил» → дообучение |
| **Дерево проектов** | Вложенная структура папок/проектов (стратегия → продукт → объект) с общим входящим потоком |
| **Wiki + стандарт** | Публичная Wiki для внешней аудитории; книга — расширенный внутренний канон |
| **Риск деградации** | Нельзя бесконечно «кормить» базу без QA и критического approve человеком |
